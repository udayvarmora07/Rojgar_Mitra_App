# I18N.md — English, Gujarati and Hindi

The localization contract for Rojgar Mitra. Read this before adding a string, a number, a
date, or a language-dependent sort.

---

## 1. Stack

| Piece | Version | Why |
|---|---|---|
| `i18next` | 26.x | Mature ecosystem, CLDR plural rules through `Intl.PluralRules`, offline JSON resources, no network dependency |
| `react-i18next` | 17.x | Re-renders every screen on `changeLanguage`, hooks API |
| `expo-localization` | **17.0.9** (SDK 54) | `getLocales()` returns the device's BCP 47 tags; must match the Expo SDK's native module |

`expo-localization` is pinned to the SDK 54 version. A newer major (`55.x`) was installed
once and Expo reported it as incompatible; the packages were realigned with
`npx expo install expo-localization`. Do not hand-upgrade a native module past its SDK.

The three locale tags are `en-IN`, `gu-IN`, `hi-IN`. i18next resolves `gu`, `gu-IN` and
`gu-Gujr-IN` to the same `gu` dictionary, and an unsupported device language falls back to
English rather than to a half-translated chain.

---

## 2. What is measured, not assumed

Run locally with Node (V8 with full ICU); Hermes ships the same `Intl` surface for SDK 54.

| Measurement | Result |
|---|---|
| `Intl.PluralRules('gu').resolvedOptions().pluralCategories` | `["one","other"]` |
| `Intl.PluralRules('hi').resolvedOptions().pluralCategories` | `["one","other"]` |
| `PluralRules('gu').select(0)` | `one` (CLDR: 0 and 1 use the singular) |
| `Intl.NumberFormat('gu-IN').format(1234567)` | `12,34,567` (Indian grouping) |
| `Intl.NumberFormat('hi-IN').format(19950)` | `19,950` |
| `toLocaleDateString('gu-IN', {month:'long'})` | `નવેમ્બર` |
| `toLocaleDateString('hi-IN', {month:'long'})` | `नवंबर` |
| `Intl.Collator('gu').compare` | `અમદાવાદ < ગુજરાત < સુરત` |

Gujarati and Hindi use only `one` and `other`, so the `_one` / `_other` translation keys
are complete. There is no `_few` or `_many` form to add.

## 3. Rules

### Strings

- Add the key to `lib/locales/en.ts` first. `TranslationShape` is derived from it, and
  `lib/locales/gu.ts` / `hi.ts` are typed against it, so a missing translation is a type
  error. `__tests__/i18n.test.ts` also asserts key parity, no blank values, and matching
  `{{placeholders}}`.
- `i18next.d.ts` types every `t('...')` key. Dynamic labels (`level.labelKey`,
  `category.labelKey`, `group.titleKey`) are typed as `TranslationKey`, never `string`.
- Keep sentences short and concrete for the audience. Prefer "Last Date" over "Application
  closing date"; prefer "posts" over "vacancies" in body copy.

### Numbers

Inside a translation, use i18next's built-in formatter for any number the reader sees:

```ts
// lib/locales/en.ts
jobsCount_one: '{{count, number}} job',
jobsCount_other: '{{count, number}} jobs',
```

This keeps plural selection on the numeric `count` and formats the printed value with the
active language's `Intl.NumberFormat`. A plain `{{count}}` prints `1234`, not `1,234`.

Outside a translation, use `lib/format.ts`:

| Helper | Use |
|---|---|
| `formatNumber(n, language)` | counts, vacancies, scores |
| `formatPercent(ratio, language)` | progress and result percentages |
| `formatScore(score, total, language)` | `7/10`, `1,200/2,000` |
| `compareNames(a, b, language)` | sorting departments and other user-visible names |

### Dates

Always use `formatDate(value, language, style)` or `dateParts(value, language)` from
`lib/deadline.ts`. They use the locale from `constants/languages.ts` and fall back to the
product's `18 Nov 2026` order if a device lacks the locale's `Intl` data. Never call
`toLocaleDateString` directly in a screen.

### Detection

`lib/deviceLanguage.ts` walks the device's **ordered** locale list. A phone set to
`fr-FR, hi-IN` opens in Hindi; only when no locale maps to `en`, `gu` or `hi` does it fall
back to English. Regional tags (`gu-IN`, `hi_IN`) map to their base language.

### Language persistence

`app/_layout.tsx` restores the saved language before rendering the router, so the first
paint is never English for a Gujarati/Hindi user. The choice is stored under
`settings:language:v1`; "Clear saved data" deliberately keeps it.

## 4. Adding a language

1. Add the code and locale tag to `constants/languages.ts`.
2. Copy `lib/locales/en.ts` to `lib/locales/<code>.ts` and type it as `TranslationShape`.
3. Register it in `lib/i18n.ts` under `resources` and `supportedLngs`.
4. Add the language to `LanguageOptions` in `components/ui/LanguagePicker.tsx`.
5. Run `npm run typecheck`, `npm run lint`, `NODE_ENV=test npx jest`.
6. Verify the script renders: the test in `__tests__/i18n.test.ts` only asserts Gujarati
   and Hindi today; add the new script check there.

## 5. Production score

**9/10.** The remaining point is human, not technical: a native Gujarati and Hindi speaker
should review the copy for tone and for terms like "અનુસ્નાતક" / "परास्नातक". A translation
management platform (Locize/Crowdin) and Android/iOS per-app language preferences would
make it a 10 for a larger team, but neither is needed for three bundled dictionaries of
this size.
